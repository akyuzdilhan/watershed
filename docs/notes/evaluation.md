# Evaluation harness: definitions and findings

`python -m worker.evaluate --seeds 100 --timing --out docs/evaluation.md [--json evaluation.json] [--bench data/bench]` runs the generator on unscripted seeds 1 to N plus the committed demo replay, the pipeline with the desk (template writer, auto-approve, in-memory sink), the Verifier, and replays every stream under extra perturbations. No Azure, no model call. The report is deterministic for a given seed range; only section 6 (processing time, `--timing`) changes from one run to the next. `tests/test_evaluate.py` checks it on seeds 1 to 3 and the demo.

## Feed time

Every message is handed to `Pipeline.handle(m, now=t)` with `t` its arrival time on the broadcast clock. Without perturbation `t = emitted_at_s`, which is what `Pipeline.handle(m)` uses by default. A result (card or card action) is stamped with the `t` of the message whose arrival released it from the reorder buffer; results released by the final `flush()` get the last arrival plus `hold_s`.

## Metrics

| Metric | Definition |
|---|---|
| Goal recall | Truth goals (`truth.goals`, disallowed ones included: their card must exist before it is retracted) with a card of kind `goal` on the same event id, over all truth goals. |
| Red card recall | Truth cards `red` or `second_yellow` with a `red_card` card on the same event id. |
| Planted save recall | Demo only: `save` moments of the truth (event id = the shot) with a `save` card whose `shot_event_id` is that shot. |
| Card precision against truth moments | Cards matching a truth goal, red card or planted save, over all cards. The unscripted truth plants no moment, so chance and save cards cannot match anything and pull this number down by design. |
| Card classes | `truth_goal`, `truth_red`, `truth_save` (above); `extra_chance` and `extra_save`: the card's shot is in `truth.shots` with the outcome the card claims (chance: not goal and not saved; save: saved) and, for a save, the keeper's action is the message right after the shot (`seq + 1`, true for all 673 saved shots of seeds 1 to 100); `mispaired_save`: a save card whose keeper action is not that one; `ungrounded_*`: no matching truth shot. |
| Cards grounded | `truth_*` plus `extra_*`, over all cards. |
| Card actions | For each truth goal, expected `expected_card_action` (none, retract, rewrite) against what the Spotter did on its card: `retract`, `rewrite`, both in order, `none`, or `no card`. Correct when they are equal. |
| False retraction / rewrite | A retract (rewrite) on any card whose event is not a truth goal expecting a retract (rewrite). |
| VAR checks handled | Truth VAR checks on an event that has a card: a `hold`, then `release` if the decision is `stands`, `retract` if `overturned`. |
| Score | `Match.score()` at full time equals `truth.final_score`. |
| Value | `value_pts` of each card, by kind; bins 0-4, 5-9, 10-19, 20-29, 30-49, 50+. |
| Robustness | The stream is replayed with arrival times changed (messages untouched), sorted by arrival. Identical: same cards (kind, status, version, team, player, shot, value, facts, score before), same set of card actions (card, action, message id), same final score as the unperturbed run. Run without the desk. Perturbations: 0-2 s jitter on every message; 5 % duplicates resent 0-60 s later; 5 % delayed 0.5-2.5 s; a mix of the three (all within the 3 s buffer); beyond the buffer: 0-6 s jitter, 5 % delayed 4-10 s, 2 % delayed 30-120 s, and a targeted one where each goal that gets a void or reassign arrives 5 s after its correction (only matches with such a goal). Seeded with `random.Random(f"{name}-{seed}")`. |
| Action to card | Arrival time of the release minus the action's `wall_s` (for a save, the shot's `wall_s`). Split into provider latency (`emitted_at_s - wall_s` of the action message, first copy) and worker wait (release time minus `emitted_at_s`). |
| Card to retract / rewrite | Release time of the action minus release time of the card; also correction message `wall_s` to the action. |
| Demo window | For each demo moment expecting a retraction: card ready, card to hold (VAR check starts), card to retraction (VAR decision), and the check's length. This is the time a producer has to air the card before VAR takes it back. In the live replay `generator.publish.schedule` paces corrections (`min_correction_delay` 40 s), so the live window can differ from feed time. |
| Writer | Audit entries `written` with `verified` true, over all writes (first versions and rewrites); then the final texts of each card re-run through `verify()` with `card_facts()`; length limits; any `0%` or `100%` in a text. |
| Benchmark | `data/bench/*.jsonl` from `spikes/af_trial.py`, only read: per model and effort, runs, errors, JSON valid, cards verified (counted only when the run returned the right languages, as in `spikes/bench_report.py`), traps held, median seconds per card. `data/` is git-ignored, so the section only appears where the files exist; the committed report was generated with `--bench` pointing at the main checkout's `data/bench`. |

## Findings (bugs in other modules, not fixed here)

1. **A save can be credited to a later, unrelated save** (`worker/spotter.py`, `Spotter.saves`). A saved shot above the threshold waits in `saves[keeper_team]` for the next `keeper_save` of that team, with no check that it is the action right after the shot and no expiry. When the shot reaches the worker after its keeper action (the shot is one of the feed's own late messages, beyond the 3 s buffer), the keeper action is processed first and gives no card, then the shot is parked and paired with the next keeper save of that team. Seed 53: shot `synthetic-0053-v2-a00445` at 27' (seq 447, emitted 10 s late), keeper save seq 448 processed before it; the card `card-synthetic-0053-v2-a01267` comes out at 73' with the 27' shot's facts, 3959 broadcast seconds after the shot. The 27' save gets no card. Flagged as `mispaired_save` in the report; it is also every difference in the beyond-buffer robustness rows (a missing save card, sometimes an extra one later). Test: `test_a_save_card_credits_the_keeper_action_right_after_its_shot` (xfail). Checking `keeper["seq"] == shot["seq"] + 1` would close it.
2. **A correction that arrives before its action is lost** (`worker/match.py`, `Match._apply`; `worker/spotter.py`, `process`). A `reassign` or `update` whose target has not been applied yet is dropped (`target is None`), and the action, when it comes, is stored in its original version. The Spotter ignores a correction or VAR check on an event it has no card for. On the demo, with goal 31' delivered 5 s after its reassignment, the card keeps the first scorer (`away-10`) and is never rewritten; with goal 69' delivered after its void, the Spotter cards a goal that is already voided (value 0, status stays proposed, so on air in auto-approve mode) and never retracts it. The final score stays right. The feed's own late messages (4-10 s) are far shorter than the gap between a goal and its correction (48 s or more), so only the targeted perturbation triggers it. Test: `test_a_goal_that_arrives_after_its_correction_still_gets_the_right_card_action` (xfail).
3. **The buffer only releases on arrival** (`worker/match.py`, `release`). There is no timer: a gap is given up when a later message arrives at least `hold_s` after the oldest pending one was emitted, so a card can wait longer than `hold_s` (worker wait up to 7.3 s on 100 seeds, against a 3 s buffer). With few messages, for example during a stoppage, a held card waits for the next message; `Pipeline.flush()` is only called at the end of a Service Bus session.
4. **Processing time went up about 28 times with the match-state change** (commit 564972d). `Pipeline._process` now predicts the win probability after every action for `wp_timeline`, and `Match.state` scans every stored action (`score`, `reds`) and every processed message (`added_time`, `full_time`): quadratic in the match length. Seed 1 (1567 messages): 0.045 s per match before, 1.3 s after, about 0.8 ms per message. Harmless live (one message every few seconds), but the evaluation over 100 seeds with its replays now takes about 24 minutes instead of 80 s, and the full test suite about 5 minutes.
5. **Verifier name check** (`worker/writer.py`, `names_ok`). `verify` joins headline and why with a space, so the first word of `why` is not seen as the start of a sentence: the template's "The", "La" and "L'arrêt" are flagged on every save card. Informative only, since `verified` does not use it.

## Caveats

- The unscripted truth has no planted moments, so precision against truth moments mostly measures how many chance and save cards the 8-point threshold lets through; grounding is the better safety number for those cards.
- Seeds 1 to 100 contain no disallowed goal: the 33 VAR checks on carded goals all end with the goal standing. Retraction is therefore only exercised by the demo (2 cards); rewrites are exercised on 16 unscripted goals. More seeds, or a generator setting with more missed offsides, would be needed to measure retractions on unscripted play.
- In the demo truth, the `team` of a foul moment (`yellow-41`, `red-78`) is the fouled team, not the carded player's (`director.Moment.side`); the harness matches red cards on `truth.cards`, which carries the offender's team.
- Robustness runs use the pipeline without the desk; the desk only adds texts and statuses on top of the same Spotter results.
